# C 标注与评测规范 v1

真实评测资料须先固定原始文件 SHA-256、来源 URL、披露日、公司代码、期间与合并/母公司口径。不要把本仓库虚构公司 999999 当成真实样本。`demo/fixtures` 只验证代码行为；真实样本尚未收集和双人标注，不能报告真实精确率。

每个可独立判断的声明记录：`claim_id, company_code, split, draft_document_id, draft_evidence_id, sentence, source_evidence_ids, calculation_id, annotations`。原句定位由 A 返回的 Evidence 固定，坐标为 0—1000、页码从 1 开始。含两个指标的句子应人工拆分；目前规则基线保留整句待复核。不可将草稿自身作为财务事实来源。

两名成员独立填写 annotations：`annotator, decision, error_type, reason`。相同 annotator 不构成双人标注。分歧由第三名成员填写 `adjudicator, decision, error_type, reason` 后调用 `eval.metrics.adjudicate`。代码生成的样例真值不代表已完成双人标注。

decision 为 correct / incorrect / needs_review。缺独立证据、含混期间、预测/条件句或多版本事实优先 needs_review。error_type 沿用公共契约；只有找到明确反证才判 number、unit 等错误。B 复核金融规则与来源，C 不代签人工核验结论。

按公司而非句子随机划分 development / holdout；同公司所有年度/文档留在同一集合。开发集用于规则调整，留出集在规则与模型版本冻结后运行。`check_company_split` 拒绝公司泄漏。未提供预测的金标计为弃权，错误金标的弃权计入漏报；多余/重复预测拒绝评测，防止虚高指标。

指标以“incorrect 为阳性”报告 precision、recall、false_positive_rate、覆盖率、三分类准确率、错误类别准确率、缺预测数、混淆计数及失败清单。待复核金标被判错误单独计数，也计入精确率分母；误报率只在已核实正确声明上计算。分母为零返回 null，不填 100%。数值字符串为 0—1 比率，仅评测内部使用，不是公共金融百分数。

结构化提取与财报分析真实输出由 A/B 提供；可按字段构造内部 claim_id 后使用同一比对框架，关键金额须用 Decimal 比较并记录原始页码。该分类评测器不宣称已完成 A/B 数值准确率实测。

2026-10-12 补充：`python -m eval.annotations template` 可从实际核查 TaskResult 生成不预填系统决策的空白模板；`combine` 验证两份独立标注与第三人裁决并导出金标，保留结果与标注哈希。使用命令和私有文件说明见 `demo/角色C交接单.md`。工具通过不表示真人独立标注已完成。
