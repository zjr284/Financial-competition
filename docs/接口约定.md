# 接口约定 v1.0.0

本文件给人阅读；`contracts/contracts.schema.json` 给程序校验；`contracts/openapi.yaml` 定义 HTTP 接口。三者冲突时先停止联调，按 `docs/接口问题记录.md` 决议后同步修改。

## 1. 通用规则

| 项目 | 约定 |
|---|---|
| API 路径 | `/api/v1`；JSON 内容类型 `application/json`，文件上传使用 `multipart/form-data` |
| 版本 | 请求及结果带 `api_version: "1.0.0"`；破坏性变更提升主版本 |
| 标识符 | `doc_`、`ev_`、`fact_`、`run_`、`calc_`、`review_` 前缀加 UUID 或稳定短 ID；不可用公司简称代替 ID |
| 时间 | 日期 `YYYY-MM-DD`；时间 ISO 8601 且带时区；财务区间两端均包含 |
| 数字 | 金额、比例、倍数全部为十进制字符串；金额内部单位人民币元 `CNY`，股数 `share`，百分数 `percent`，倍数 `times`；不使用二进制浮点数入库 |
| 百分比 | `"12.5"` 代表 12.5%；同比为 `"-8.2"` 表示下降 8.2%；展示层补 `%` |
| 缺失值 | 可缺失的数值为 `null` 并附 `reason`；禁止填 `0`、`-` 或臆测值 |
| 坐标 | `bbox=[x0,y0,x1,y1]`，整数 0—1000，左上角为原点，先按 PDF 旋转后页面归一化；页码从 1 开始 |
| 状态 | 任务 `queued/running/needs_review/succeeded/failed/cancelled`；事实 `verified/needs_review/rejected` |
| 证据 | 每条提取字段、财务事实、研报核查和报告事实至少含一个 `evidence_id`；派生值可用 `calculation_id` 串回输入事实 |
| 安全 | 固定资料包内运行；上传仅允许 PDF、TXT、CSV、XLSX；限制文件大小与页数的具体数值由部署配置设定并写入 README |

**原文证据与观点的关系：** 原文直接支持的内容记 `fact`；工具运算记 `calculation`；模型综合解释记 `inference`；投资判断记 `opinion`。后两者必须说明前提、反证或局限，不能伪装为原始披露事实。

## 2. 公共实体

**Document**：`document_id, filename, media_type, sha256, source_url, disclosure_date, ingested_at, page_count, parse_status`。同一文件内容哈希可重复上传，但须返回相同或明确关联的文档版本；更正公告是新文档，不能覆盖旧文件。

**Evidence**：`evidence_id, document_id, page, bbox, text, extraction_method, confidence`。`text` 是短原文片段；完整文件通过文档服务查看。表格来源另带 `table_id, row, column`，行列从 1 开始。OCR 结果的 `confidence` 是解析置信度，不等同事实真实性。

**Fact**：`fact_id, company_code, metric, value, unit, period_start, period_end, period_type, statement_scope, restated, evidence_ids, review_status`。`period_type=instant` 的起止日期相同；流量可为 `cumulative` 或 `single_quarter`。`statement_scope=consolidated/parent/not_applicable`。数值为 `null` 时必须有 `reason`。

**Calculation**：`calculation_id, formula_code, input_fact_ids, input_calculation_ids, parameters, value, unit, rounding_rule, status, reason`。计算过程不得只存一段自然语言。比率基期为零、口径不一致、缺值时，`value=null`、`status=needs_review`、写明原因。所有计算只放在 `TaskResult.calculations`，各题 `data` 用 ID 引用。

**Run**：`run_id, task_type, status, document_ids, created_at, started_at, finished_at, model_id, model_revision, prompt_version, code_version, input_hash, result_hash, error`。状态转换只允许 `queued → running → succeeded/needs_review/failed`，`needs_review → running/succeeded/failed`，以及未完成状态到 `cancelled`。

**Error**：固定结构 `{code, message, details, retryable, run_id}`。代码见 Schema，包括 `VALIDATION_ERROR`、`DOCUMENT_UNSUPPORTED`、`FILE_TOO_LARGE`、`RESOURCE_NOT_FOUND`、`EVIDENCE_NOT_FOUND`、`MISSING_INPUT`、`PERIOD_MISMATCH`、`SCOPE_MISMATCH`、`CALCULATION_UNDEFINED`、`MODEL_UNAVAILABLE`、`RUN_NOT_READY`、`REVIEW_REQUIRED`、`INTERNAL_ERROR`。HTTP 4xx 对调用方输入问题，5xx 对服务问题；运行中发现的业务失败写入 Run 的 `error`。

## 3. HTTP 端点

| 方法与路径 | 用途 | 输入 | 成功返回 |
|---|---|---|---|
| `GET /health` | 本地服务状态、API 版本 | 无 | `Health` |
| `POST /documents` | 上传并登记文件 | `file`，可选 `source_url`、`disclosure_date` | `201 Document` |
| `GET /documents/{document_id}` | 文件元数据 | 路径 ID | `Document` |
| `GET /documents/{document_id}/content` | 读取原始文件，供证据页定位 | 路径 ID | 原始字节流；Content-Type 为文件 MIME，ETag 为 SHA-256 |
| `POST /runs` | 启动七题之一 | `RunRequest` | `202 Run` |
| `GET /runs/{run_id}` | 查询进度、失败或待复核 | 路径 ID | `Run` |
| `GET /runs/{run_id}/result` | 取得结构化结果 | 路径 ID | `TaskResult`；`succeeded` 与 `needs_review` 均可读取，运行中返回 409 |
| `GET /runs/{run_id}/events` | 取得工具与状态事件 | 路径 ID，可选 `cursor` | `EventPage` |
| `GET /evidence/{evidence_id}` | 查看证据位置与片段 | 路径 ID | `Evidence` |
| `POST /reviews/{review_id}/decision` | 人工接受、驳回或修正 | `ReviewDecision` | `ReviewItem` |

`POST /runs` 中 `task_input` 按 `task_type` 区分。前端提交后轮询 Run；状态为 `succeeded` 时读取 result；状态为 `needs_review` 时展示 `review_items`。每次运行都固定输入文件 ID，不能在运行途中更换资料。所有端点返回 `X-Request-Id` 便于排查。

## 4. 七题输入与输出

| 任务代码 | `task_input` 必填 | `data` 的稳定顶层键 | 核验要点 |
|---|---|---|---|
| `structured_extraction` | `announcement_types` 数组 | `records`（每条含 `event_id, announcement_type, fields`） | 每个字段含原值、归一值、单位、证据、状态 |
| `financial_analysis` | `company_code, periods, statement_scope` | `facts, alerts` | 同比同期间、同口径；计算在公共 `calculations`，异常卡片给来源与严重度 |
| `industry_impact` | `focus_company_code, event_description, scenario_ids` | `nodes, edges, scenarios, conclusions` | 每条路径给方向、假设、来源、适用边界 |
| `valuation` | `company_code, method, as_of_date, statement_scope`；可选 `assumption_overrides` | `assumptions, valuation_range, sensitivity` | 计算在公共 `calculations`；折现／可比口径及行情时点明确 |
| `research_verification` | `draft_document_id, company_code` | `checks, summary` | 每条声明标正确／错误／待复核、错误类型、改写建议 |
| `investment_memo` | `company_code, as_of_date` | `thesis, evidence, risks, disconfirming_conditions, monitoring_indicators` | 事实、推论、观点分层，包含反证和跟踪指标 |
| `report_quality` | `report_document_ids` | `rubric, report_scores, review_items` | 扣分项给原句和证据；重复运行报告一致性 |

`TaskResult` 固定包裹层：`api_version, run_id, task_type, status, generated_at, input_document_ids, data, evidence_ids, calculations, review_items, warnings`。七题的 `data` 内部字段按 Schema 定义；不能返回只有自然语言的对话记录。`warnings` 用于缺失材料、口径冲突和模型不确定性。

**字段字典 v1：** 提取记录固定包含 `document_id, company_code, event_date`；质押公告字段 `shareholder, pledged_shares, pledged_ratio, pledge_start_date, pledge_end_date, pledgee`；中标公告字段 `project_name, winning_party, contract_amount, currency, performance_period`；股权变动字段 `holder, shares_before, shares_after, ratio_before, ratio_after, change_method`。非适用字段可省略；必填但找不到值时保留字段、`value=null, status=needs_review, reason`。

**常用财务指标代码：** `revenue` 营业收入、`net_profit_parent` 归母净利润、`net_profit_parent_excl_nonrecurring` 扣非归母净利润、`operating_cash_flow` 经营现金流净额、`total_assets` 总资产、`total_liabilities` 总负债、`accounts_receivable` 应收账款、`inventory` 存货。新增指标先写入指标字典，不能让不同模块使用不同拼法。

**公式代码：** `yoy=(current/prior-1)*100`，输出百分数值；`quarter_from_ytd=current_ytd-prior_ytd`，仅适用流量；`cash_conversion=operating_cash_flow/net_profit_parent`，输出倍数；`gross_margin=(revenue-cost_of_revenue)/revenue*100`，输出百分数值；`pe=market_cap/net_profit_parent_ttm`，输出倍数；`dcf_enterprise_value=sum(discounted_fcf)+discounted_terminal_value`，输出人民币元。基期为零、负利润下 PE 无经济意义、股价快照缺失等场景应标 `needs_review`。

## 5. 内部 Python 接口

Python 模块按 [`contracts/ports.py`](../contracts/ports.py) 的 `Protocol` 实现。任务模块只返回 `data, evidence_ids, calculations, review_items, warnings`；编排器负责补齐 `TaskResult` 的运行 ID、版本、状态和时间。解析器不直接拼报告文字。核心签名如下：

```python
def ingest_file(path: str, metadata: dict) -> dict: ...  # Document
def parse_document(document_id: str) -> dict: ...       # ParseManifest: evidence_ids, warnings
def get_evidence(evidence_id: str) -> dict: ...         # Evidence
def extract_facts(document_ids: list[str], field_codes: list[str]) -> list[dict]: ...
def calculate(formula_code: str, input_fact_ids: list[str], input_calculation_ids: list[str], parameters: dict) -> dict: ...
def infer_json(task_code: str, evidence_ids: list[str], schema_name: str, context: dict) -> dict: ...
def run_task(request: dict) -> dict: ...                 # TaskResult
def append_event(run_id: str, event: dict) -> None: ...
```

`infer_json` 必须保存模型 ID、修订号、提示词版本、输入证据 ID 和输出哈希。工具调用不得绕过 `append_event`；重试沿用同一个 `run_id` 并记录尝试次数。模块未完成时可用符合 Schema 的固定样例联调，但展示页面必须显式标记为样例。

## 6. 版本与改动流程

公共契约先冻结 v1。增加可选字段提升次版本，修正文档或示例提升补丁版本；删除字段、重命名或改变金额口径须提升主版本，并提供迁移脚本。修改顺序：记录问题 → 改 Schema → 改 OpenAPI → 改样例 → 三人评审 → 改实现 → 运行契约校验。每位成员的 AI 助手在接到子任务前，应被告知本文件路径及当前版本，输出不得自行重新定义公共字段。
