# 语义修订的只读回归验收

A/B 本地入口 `python -m app.tasks.synthesis_acceptance` 将既有修订计划用作**指定字段的精确回归断言**，补足“只修正文却遗漏假设／边”以及“续行只放顶层、未落在陈述本身”的自动检查。它不调用模型、不生成或覆盖 Run、不修改事实状态，不依赖云端密钥。

## 运行

持有完整私有运行存储时，直接检查既有候选，无需发送新压缩包：

```bash
PYTHONPATH=vendor/python python -m app.tasks.synthesis_acceptance \
  --run-dir PRIVATE_STORE/runs/EXISTING_RUN \
  --plan samples/semantic/c_second_review/industry.json

PYTHONPATH=vendor/python python -m app.tasks.synthesis_acceptance \
  --run-dir PRIVATE_STORE/runs/EXISTING_MEMO_RUN \
  --plan samples/semantic/c_second_review/memo.json \
  --bind header=EXISTING_HEADER_EVIDENCE \
  --bind first_line=EXISTING_FIRST_EVIDENCE \
  --bind continuation=EXISTING_CONTINUATION_EVIDENCE
```

证据绑定取自原固定资料，不能自行编 ID；`append_source` 要求原引用与续行互不重复、全部属于该 Run 的固定定性来源清单，最终该条引用列表与预期完整相等。仅在结果顶层或其他陈述追加引用不能通过。`replace` 要求目标字段与计划 `value` 完整相等，覆盖正文、假设、限制、边和情景；空计划、重复路径或缺绑定均拒绝。也可在私有计划中为归因原句、归因限制添加明确的 `replace` 预期。计划需要先依据来源审阅；工具不会自己判断正确措辞，也不会自动从待测输出生成“标准答案”。语义相同但措辞不同仍会失败，需重新审阅并固定计划，不能为获得通过而盲目更新预期。

入口先校验原登记 Run、初始 manifest 元数据与 input_hash、结果 Schema 及登记 result_hash；读取数据库采用 SQLite `mode=ro` 的一致读取事务，复用既有事件链校验，再核对固定来源清单与原事件哈希。缺完整登记库、固定快照或事件时明确失败，不从全局清单补值，也不退回网络。运行期间会使用 SQLite 自身的读取锁／共享内存，不写业务数据或源文件。

退出码为 0 只表示**计划指定字段**全部匹配；字段不匹配、字段消失或完整性检查失败退出 1。摘要含检查编号、布尔结果及输入／结果／计划／绑定／来源摘要，不打印原句、证据 ID、定位、财务值或本机路径。格式错误仅输出固定 `VALIDATION_ERROR`；无论通过与否都输出 `human_gold=false` 和 `review_status=needs_review`。

这不是完整重放，不重新解析 PDF，不证明原件坐标、证据语义蕴含、未指定字段或云端准确率，也不替代 C 的审查、真人双标及留出集。内部哈希是一致性检查，不是独立签名。公共 Schema 和 C 的 demo/web/eval 均未更改。

## 本轮验收

使用 PR17 已核对的真实来源及原修订计划，只读检查已有新旧 Run：产业链旧稿五个指定字段均失败，新本地工程稿五个字段均通过；备忘录原稿的该条续行引用失败，新工程稿通过。保留全部旧稿、原云端失败候选、现有事实状态和原财务清单；没有生成新云端结果，没有新增金融签署。这只是既定工程反馈的回归证明。

合成测试覆盖独立的假设／边遗漏、归因丢失、顶层引用不能替代逐条引用、未知来源／缺绑定、空计划／字段缺失、结果／来源／输入／事件篡改、读取前后业务文件不变，以及命令行脱敏失败。真实检查详细摘要留在私有监控目录，不提交真实结果或底稿。最终测试数量和契约结果见本 PR。
