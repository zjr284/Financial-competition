# 公告模型候选与语义来源归属（2026-10-15）

PR #11 已合并，后续 A/B 开发从 main 的 `5a4670c` 开始。本轮接入公告模型候选，并补齐产业链和备忘录的公司来源边界。公共 Schema、OpenAPI 和 C 模块不变。

## A：显式启用模型候选

默认仍为 rules。只有配置 `FINSCOPE_EXTRACTION_BACKEND=model`，结构化提取才调用已配置模型；不因密钥文件存在自动联网。

在模型环境变量已按 [运行说明](模型与语义任务运行说明.md) 配置、代码版本也已登记的终端执行：

```bash
export FINSCOPE_EXTRACTION_BACKEND=model
python3 -m app.cli run structured_extraction --documents DOCUMENT_ID --announcement-types pledge
```

模型接收前两页至多十六个短窗口，每窗口至多三百字符；质押公告在累计持仓章节之前截断，避免把存量当作本次交易。使用临时文档和证据别名，不发送本机路径、真实文档 ID、定位坐标或人工复核历史。当前不是完整文档抽取。

对于有完整横竖边框的原生 PDF，可另设 `FINSCOPE_EXTRACTION_GRID=true`。该选项默认关闭，仅对 model 模式生效；最多恢复前两页、六十四个数据单元格，另保留十六个短文本窗口。只接受闭合网格，不猜测缺失边框或扫描图表。表头作公开文字提示，行列号、坐标、表格 ID 不发送给模型；原值仍必须出现在单个实际单元格内。原解析缓存及既有事实定位不改写。

模型只提供 raw_value 候选。处理端校验字面原文及引用，再用现有 Decimal 归一化工具生成金额、股数、百分数和日期，忽略模型给出的 value、unit、verified 状态和 event_id。记录归属仅从原文证券代码表头确认，不制造占位公司代码；元数据遗漏不会直接丢弃有表头支持的记录。

模型候选字段全部保留 needs_review。无法定位、缺单位、歧义比例、无效公历日期和币种不明都保留 null 与原因；解除质押日不是确定日期。外币不直接标成人民币。表头与交易行仍须独立核对，字面匹配不等于列映射正确。

内部 input_hash 在 model 模式下额外绑定提取模式和显式网格选项。重放须恢复原模式和版本，关闭云端模型后读取固定响应；不在网络失败时回退规则结果冒充模型输出。默认 rules 的历史输入结构不变。

## A 的真实成功与待复核样例

使用巨潮资讯官方的欣旺达股份质押公告：[2026-09-22 原件](https://static.cninfo.com.cn/finalpage/2026-09-22/1225576272.PDF)、[2026-07-01 原件](https://static.cninfo.com.cn/finalpage/2026-07-01/1225403052.PDF)。PDF 已下载、登记披露日、固定 SHA-256，并经过真实文本层解析。

| 案例 | 模型候选记录 | 本地对照结果 | 继续待复核 |
|---|---|---|---|
| 9 月公告 | 2 条 | 原生网格恢复后，股数、占总股本比例、起始日期及质权人全名与 AI 阅读原表一致 | 解除质押时到期，不能编造日历日期 |
| 7 月公告 | 1 条 | 同上；上标脚注按同一文本行的横向位置保留，不混入股数 | 解除质押时到期，不能编造日历日期 |

首轮曾发生记录级字段遗漏导致零记录，以及网络失败；原 Run 保留。网格开发还发现上标“注3”被错误排在数量前，造成脚注数字混入股数。已修复字符行归组，并增加原值拒绝及回归用例；错误响应未覆盖为通过结果。最终两份公告都产出符合 Schema 的待复核结果、JSON/HTML 导出及一致的离线重放。以上只是开发集 AI 对照，不是人工金标、字段召回率或精确率。

来源定位输出保存在私有 extraction_locations 与 grid_locations，包含每字段对应的原文、页码和 bbox。网格字段引用单元格区域，元数据仍可引用短窗口；未完成 C 的页面框选验收。实际数值、ID、原始模型响应和运行快照不上传公开仓库。

## B：绑定公司与通用行业范围

登记公司资料：

```bash
python3 -m app.facts.semantic_sources --data-dir PRIVATE_STORE --manifest PRIVATE_MANIFEST --document-id DOCUMENT_ID --evidence-id EVIDENCE_ID --company COMPANY_CODE
```

只有通用行业资料才用 `--scope industry`，不带 `--company`。该声明不等于已核实内容。公司绑定须为六位证券代码，不能与文档已有事实冲突，也不能直接改绑已登记片段。旧清单未声明归属的片段保留为 unclassified，新任务排除它们；须确认来源后显式补上归属，不覆盖历史 Run。

产业链和备忘录都筛掉其他公司的片段；备忘录同时保留披露截止日门槛。模型接收公开披露日，但提示明确区分披露日、报告期、管理层自述和已实现结果。

B 的真实验证使用欣旺达 2025 年报、2026 年半年报两份已归档原件，共十五条定性片段、678 字符。副本中的财务 facts 为空，不上传原始财务台账。两条任务均通过 Schema、引用归属、JSON/HTML 导出和冷启动离线重放；AI 抽查保留了管理层自述的限制及客户成本与公司成本的区分，结果仍 needs_review。既有四十五项确认事实及人工历史的总清单前后哈希一致。

新增独立来源为 [国家能源局 2026-07-30 保供发布](https://www.nea.gov.cn/20260730/44149332963f44e3896720d8c02b9cc7/c.html)。公开的 [短摘录](../samples/semantic/nea_grid_flexibility_20260730_excerpt.txt) 和 [来源说明](../samples/semantic/nea_grid_flexibility_20260730.provenance.json) 可复用：声明 industry、不绑定公司；哈希固定的是摘录 TXT，非原始网页 HTML。浏览器核对了来源与发布日期，未将其登记为已确认财务事实。

以公司半年报四条定性片段和行业摘录三条片段组成独立资料包，产业链与备忘录都完成真实调用、Schema、导出及冷启动重放。产业链首轮网络失败后重试成功，失败 Run 保留。条件情景专门要求区分境内调度调用与海外家庭／工商业储能销售，未把调度增加等同新增装机、订单或利润。AI 对照也发现部分管理层自述的归因仍不够明确；待分析员确认，不能以带引用或 Schema 通过代替语义验收。

真实产业链响应曾在正文插入临时 ev_model 引用。现在仅在 text、mechanism、impact_text 显示字段还原，且须同时在该声明的 evidence_ids 中列明；未知或未声明引用拒绝，抽取 raw_value 不改写。已用本机 HTTP 和固定真实候选分别验证。此前 Run 保留原输出，新归一化证明单独保存，不把本地再处理称为新云端生成。
